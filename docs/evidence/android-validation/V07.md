## Findings and gate hardening during V07

Three validation-script portability defects were exposed before the authoritative PASS. They were test-harness failures, not production dependency/precision failures:

1. Windows PowerShell 5.1 does not expose the newer `String.Contains(string, StringComparison)` overload used by the first gate revision. The invariant checks were changed to `IndexOf(..., StringComparison)`.
2. Under Windows PowerShell strict mode, direct `.PSObject.Properties.Name` enumeration was not portable for the deserialized `project.assets.json` object. The gate now iterates each property object and reads its `Name` explicitly.
3. The Windows PowerShell/.NET Framework runtime rejected the `double.ToString("R", culture)` overload used only to format evidence text. The gate now uses invariant `[string]::Format(..., "{0:G17}", ...)`.

Diagnostic runs retained by GitHub:

- run/job `32859131536` / `97838445462` — V02 prerequisite PASS; V07 failed at the unsupported `String.Contains` overload; artifact `9567414209`.
