## Denetimde bulunan gerçek açıklar

### 1. Device matrix stale idi

`docs/DEVICE_MATRIX.md` E-API36 slotu hâlâ `V01_FIX_REQUIRED` gösteriyordu. V01 daha önce authoritative self-hosted emulator run ile `VALIDATED / INFRASTRUCTURE_SMOKE_ONLY` olmuştu. Matris V01 gerçekliğiyle hizalandı; fiziksel Android slotları release farkları için deferred kaldı.

### 2. Redistributable DWG smoke girdisi yoktu

Tarihsel mini corpus 4 pinned upstream DWG + 2 pinned upstream DXF + committed sentetik DXF'ler içeriyordu. Upstream binary sample'lar bilinçli olarak `remote-reference-only` sınıfında tutulduğundan mobil-dwg tarafından redistributable bundle sayılmıyordu.

Çözüm: committed 0BSD `synthetic-turkish-basic-ac1015` DXF'den validation sırasında exact `ACadSharp 3.7.1` kullanan `scripts/stage03-generate-synthetic-dwg.ps1` ile AC1015 DWG üretilir. Generator:

- exact .NET `10.0.400` ister;
- exact ACadSharp `3.7.1` resolved graph'ını doğrular;
- DXF'i okur, eksik default CAD table hierarchy'sini `CreateDefaults()` ile tamamlar;
- `DwgWriter` ile AC1015 DWG üretir;
- output magic `AC1015` kontrol eder;
- output'u `DwgReader` ile aynı run içinde yeniden açar.

Generated DWG yalnız open-path smoke girdisidir; bağımsız engineering-fidelity golden değildir.

### 3. Windows working-tree CRLF drift'i fixture hash'ini bozuyordu

Self-hosted Windows runner'da committed sentetik DXF Git blob'u 769 byte iken uzun ömürlü working tree'de CRLF materialization nedeniyle 985 byte gözlendi. Manifestteki 769 byte ve SHA-256 `aa79ad97de188abc87f546e5919e9cc1495479eaa25b02d433900654fe2e9021` Git blob için doğruydu; manifest yanlış değildi.

Düzeltme iki katmanlıdır:

1. `.gitattributes`: `*.dwg binary`, `*.dxf -text`.
2. Authoritative committed-fixture hash doğrulaması platform-normalized working-tree bytes yerine doğrudan `HEAD:<path>` Git blob bytes üzerinden yapılır.

Bu ayrım, uzun ömürlü self-hosted worktree'nin daha önce materialize edilmiş CRLF dosyayı içerik değişmeden yeniden yazmaması durumunda da evidence hash'ini stabil tutar.
